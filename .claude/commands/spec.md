Create a new feature specification. Do NOT implement — spec only.

Steps:
1. Read `docs/specs/README.md` to get the current spec template and authoring guidelines
2. Read one recent spec in `docs/specs/` to understand the tone and level of detail
3. Ask the user (if not already provided): what is the feature name and the core problem it solves?
4. Determine today's date and a slug for the spec (e.g. `quiz-answer-evaluation`, `pdf-text-selection`)
5. Create `docs/specs/YYYY-MM-DD-<slug>.md` following the template from README.md:
   - Problem statement
   - Scope (what's in / out)
   - Goals and non-goals
   - Proposed design (API changes, data model, UI)
   - Risks and open questions
   - Test plan
   - Rollout / checklist
6. Show the draft and ask for confirmation before writing.
7. After writing, remind: "To implement this spec, start a new session referencing this file."

Keep specs focused and unambiguous — they should be implementable by Claude in a future session without clarification.
